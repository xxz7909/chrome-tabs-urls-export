# 标签会话管家

这是一个完全在本机运行的 Chrome Manifest V3 扩展，用于导出、导入、永久保存并恢复当前 Chrome 用户配置文件中的标签页会话。它可以处理多个普通窗口和无痕窗口，并尽可能保留标签顺序、置顶状态、标签组和窗口布局。

## 安装

1. 在 Chrome 地址栏打开 `chrome://extensions/`。
2. 开启右上角的“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择本项目根目录，即包含 `manifest.json` 的目录。
4. 在扩展详情页开启“允许访问文件网址”，否则 `file://` 地址可能无法被完整处理。
5. 在扩展详情页开启“在无痕模式下启用”，否则扩展无法捕获或恢复无痕窗口。
6. 可将“标签会话管家”固定到 Chrome 工具栏，方便随时操作。

扩展更新后，在 `chrome://extensions/` 中点击该扩展卡片上的“重新加载”即可应用本地代码变化。

## 快速使用

### 导出 URL

点击工具栏扩展图标：

- “当前窗口”可复制或下载最近聚焦窗口中的 URL。
- “全部窗口”可复制或下载当前 Chrome 配置文件内所有普通/无痕窗口的 URL。
- TXT 内容始终是一个 URL 一行，不包含标题或窗口分隔符，并保留重复 URL。

扩展自己的弹窗和会话管理页不会被写入导出的会话。

### 保存和恢复会话

- 弹窗中的“保存会话”会立即创建一份手动会话。
- “最近会话”可直接恢复最近的手动、自动、导入或关闭前状态。
- 恢复始终创建新窗口，不会关闭或覆盖当前正在使用的窗口。
- 若某个 URL 被 Chrome 拒绝，其他 URL 仍会继续恢复，结束后会列出失败原因。

### 会话管理器

点击“导入或管理所有会话”进入完整管理页：

- 按名称、页面标题或 URL 搜索。
- 按手动保存、关闭前状态或导入会话筛选。
- 查看窗口、标签、置顶和标签组结构。
- 重命名、删除、恢复或导出单个历史会话。
- 历史默认永久保留，也可以在管理器中按时间范围批量删除会话。

### 导入 TXT 或 JSON

在管理页选择“导入会话”，粘贴内容或选择文件，然后点击“解析并预览”。

TXT 支持：

- 带协议的完整地址，例如 `https://`、`file://`、`chrome://`、`about:` 或 `data:`。
- Windows 绝对路径，例如 `C:\Users\me\Desktop\page.html`。
- UNC 路径，例如 `\\server\share\page.html`。
- 裸域名自动补 `https://`。
- `localhost` 自动补 `http://`。
- 空行忽略，重复项保留，无法识别的行不会被当作搜索词。

TXT 可选择打开到普通窗口或无痕窗口。JSON 会按原始窗口结构恢复。

## 导出格式

### TXT

只包含换行分隔的 URL，适合复制、人工编辑和与其他工具交换。TXT 不保存窗口划分、置顶、活动页或标签组。

### JSON

JSON 使用 `schemaVersion: 1`，保存完整会话结构，包括普通/无痕窗口、标签顺序、活动页、置顶状态、标签组以及窗口位置和状态。JSON 导入前会重新校验和规范化，不使用文件中的可执行代码。

## 权限说明

| 权限 | 用途 |
| --- | --- |
| `tabs` | 读取当前配置文件中标签页的 URL、标题、顺序和置顶状态 |
| `tabGroups` | 读取和恢复标签组标题、颜色及折叠状态 |
| `storage` | 保存设置和最新灾难恢复状态 |
| `alarms` | 在短生命周期后台被停止后提供至少 30 秒级的实时状态捕获兜底 |
| `unlimitedStorage` | 让永久 IndexedDB 历史不受普通扩展存储配额限制 |
| `file:///*` | 请求本地文件地址访问；仍需用户在扩展详情页手动开启 |

扩展没有 HTTP/HTTPS 主机权限、没有内容脚本，也不会向外部服务器发送数据。

## 状态恢复

- 标签、窗口或标签组发生变化后，后台内的防抖计时器约 2 秒更新“最新非空状态”。
- 不再写入永久自动快照历史；实时状态只保存在本地，供恢复流程使用。
- 安排 30 秒持久闹钟作为实时捕获兜底；Chrome 正式扩展的闹钟频率下限为 30 秒，因此不能仅靠闹钟实现 2 秒捕获。
- 浏览器再次启动时，会把上次遗留的非空状态归档为“关闭前状态”。
- 浏览器再次启动时，会先把上次遗留的非空状态归档为“关闭前状态”。
- 最后一个窗口关闭后得到的空窗口列表不会覆盖最近的有效恢复状态。

Chrome 不提供绝对可靠的浏览器退出前回调，因此“关闭前状态”是最近一次成功捕获的状态，而不是页面内存的逐字节快照。

## 常见问题

### 看不到无痕窗口

在 `chrome://extensions/` 打开扩展详情，开启“在无痕模式下启用”，然后重新打开扩展弹窗。无痕会话会按当前产品设置持久化到磁盘。

### 本地文件打不开

先开启“允许访问文件网址”。还需确认文件仍存在，且当前 Windows 用户有权读取该路径。

### `chrome://` 或其他特殊地址恢复失败

扩展会把显式地址交给 Chrome 尝试打开，但 Chrome 会阻止部分内部页面、其他扩展页面和安全敏感协议。失败地址会在恢复结果中列出，不会中断其他标签。

### 永久保存是否等于备份

不是。卸载扩展、清除扩展数据、Chrome 配置文件损坏或磁盘故障仍会删除历史。重要会话应定期导出 JSON 到其他位置。

## 平台限制

- 只能访问安装了本扩展的当前 Chrome 用户配置文件，不能跨其他 Chrome 用户配置文件或其他浏览器实例。
- 只恢复 URL 与浏览器窗口结构，不恢复 Cookie、登录状态、后退历史、表单内容、滚动位置或页面 JavaScript 内存。
- Chrome 共享标签组的共享关系不可写，恢复后会成为具有相同标题、颜色和折叠状态的本地标签组。
- 弹出式窗口、特殊协议和窗口几何由 Chrome 最终决定，平台拒绝的项目会按项报告。

## 开发验证

项目不需要安装依赖。安装 Node.js 后在项目根目录执行：

```powershell
npm test
```

测试使用 Node 内置测试运行器，不会修改 Chrome 数据。详细验证记录见 `docs/PROGRESS.md`。
